# Chaos Experiment Design

## Purpose
Produce complete, safe, runnable chaos experiments following the hypothesis-driven scientific method. Every experiment has a clear hypothesis, defined steady state, bounded blast radius, and automated abort conditions.

## Experiment Design Framework (5 Steps)

```
1. HYPOTHESIS   → "If X fails, then Y should happen, and Z metric stays within N"
2. STEADY STATE → Baseline metrics confirmed healthy before injection
3. FAULT        → Specific fault, target scope, duration, intensity
4. OBSERVE      → Monitor during injection — did system behave as expected?
5. LEARN        → Document findings, fix gaps, update runbooks
```

## Complete Experiment Example: Pod Delete

### ChaosExperiment
```yaml
# Generated by: hybrid-harness-chaos-process-prm
apiVersion: litmuschaos.io/v1alpha1
kind: ChaosExperiment
metadata:
  name: pod-delete
  namespace: <TARGET_NAMESPACE>
  labels:
    app.kubernetes.io/part-of: litmus
    app.kubernetes.io/component: chaosexperiment
    managed-by: hcprm
    experiment-category: application
spec:
  definition:
    scope: Namespaced
    permissions:
      - apiGroups: [""]
        resources: ["pods"]
        verbs: ["create", "delete", "get", "list", "patch", "update", "watch"]
      - apiGroups: [""]
        resources: ["events"]
        verbs: ["create", "get", "list", "patch", "update"]
      - apiGroups: ["litmuschaos.io"]
        resources: ["chaosengines", "chaosexperiments", "chaosresults"]
        verbs: ["create", "get", "list", "patch", "update", "watch"]
    image: litmuschaos/go-runner:latest
    imagePullPolicy: Always
    args: ["-c", "ls -lt /experiments | awk 'FNR == 2 {print $9}' | xargs -I {} sh -c './{}'"]
    command: ["/bin/bash"]
    env:
      - name: TOTAL_CHAOS_DURATION
        value: "60"          # seconds of fault injection
      - name: CHAOS_INTERVAL
        value: "10"          # seconds between pod deletions
      - name: FORCE
        value: "false"       # graceful delete (respects terminationGracePeriod)
      - name: TARGET_PODS
        value: ""            # empty = random selection from appLabel pods
      - name: PODS_AFFECTED_PERC
        value: "50"          # % of matching pods to delete per interval
      - name: SEQUENCE
        value: "random"      # random | serial
      - name: RAMP_TIME
        value: "10"          # seconds to wait before and after chaos
    labels:
      experiment: pod-delete
```

### ChaosEngine
```yaml
apiVersion: litmuschaos.io/v1alpha1
kind: ChaosEngine
metadata:
  name: <SERVICE_NAME>-pod-delete-engine
  namespace: <TARGET_NAMESPACE>
  labels:
    managed-by: hcprm
    service: <SERVICE_NAME>
    environment: <ENV>
    chaos-type: application
spec:
  appinfo:
    appns: <TARGET_NAMESPACE>       # Target namespace
    applabel: "app=<SERVICE_NAME>"  # Pod selector label
    appkind: deployment             # deployment | statefulset | daemonset
  chaosServiceAccount: litmus-admin
  monitoring: true                  # Expose Prometheus metrics
  jobCleanUpPolicy: retain          # retain | delete (keep for debugging)
  annotationCheck: "true"           # Only target pods with chaos annotation
  engineState: active
  experiments:
    - name: pod-delete
      spec:
        probe:
          # ── HTTP Probe: service must keep responding ──
          - name: application-health-check
            type: httpProbe
            mode: Continuous        # Check throughout entire experiment
            httpProbe/inputs:
              url: "http://<SERVICE_NAME>.<TARGET_NAMESPACE>.svc.cluster.local/health"
              insecureSkipVerify: false
              method:
                get:
                  criteria: "=="
                  responseCode: "200"
            runProperties:
              probeTimeout: 5s
              interval: 5s
              retry: 2
              probePollingInterval: 2s
          # ── Prometheus Probe: error rate must stay < 5% ──
          - name: error-rate-check
            type: promProbe
            mode: Edge              # Check at start and end
            promProbe/inputs:
              endpoint: "http://prometheus.monitoring.svc.cluster.local:9090"
              query: |
                sum(rate(http_requests_total{
                  namespace="<TARGET_NAMESPACE>",
                  pod=~"<SERVICE_NAME>.*",
                  status=~"5.."
                }[2m])) /
                sum(rate(http_requests_total{
                  namespace="<TARGET_NAMESPACE>",
                  pod=~"<SERVICE_NAME>.*"
                }[2m])) * 100
              comparator:
                type: float
                criteria: "<="
                value: "5.0"        # Max 5% error rate allowed
            runProperties:
              probeTimeout: 10s
              interval: 30s
              retry: 3
        components:
          env:
            - name: TOTAL_CHAOS_DURATION
              value: "60"
            - name: CHAOS_INTERVAL
              value: "10"
            - name: PODS_AFFECTED_PERC
              value: "50"
            - name: RAMP_TIME
              value: "10"
```

## Experiment in Harness Pipeline

```yaml
- step:
    name: Chaos - Pod Delete
    identifier: chaos_pod_delete
    type: Chaos
    timeout: 10m
    spec:
      experimentRef: <EXPERIMENT_UUID_FROM_HARNESS_HCE>
      expectedResilienceScore: 80    # Minimum score to pass (0-100)
    failureStrategies:
      - onFailure:
          errors: [AllErrors]
          action:
            type: StageRollback
    when:
      stageStatus: Success          # Only run chaos if deploy succeeded
      condition: <+env.type> != "Production"  # Not on prod without explicit override
```

## Experiment Design Checklist

Before marking an experiment ready to run:

```
[ ] Hypothesis written in format: "If [fault] then [expected behavior] measured by [metric]"
[ ] Steady state confirmed healthy in last 10 minutes
[ ] Blast radius scoped to minimum required (namespace / label selector)
[ ] Duration appropriate: dev=30s, staging=60s, preprod=120s, prod=60s max
[ ] At least one HTTP probe OR Prometheus probe configured
[ ] Abort conditions defined (probe failure = immediate abort)
[ ] `dryRun: true` tested first
[ ] Monitoring dashboard open and visible during run
[ ] Rollback steps prepared and tested
[ ] Team notified via Slack before running in shared environments
```

## Experiment Result Interpretation

| Resilience Score | Interpretation | Action |
|---|---|---|
| 100 | System fully resilient to this fault | Increase blast radius or move to production |
| 80-99 | Good — minor degradation within tolerance | Document, schedule re-test after improvements |
| 60-79 | Partial failure — some probes failed | File ticket, fix before next game day |
| 40-59 | Significant failure — system degraded | Immediate remediation required |
| 0-39 | Critical — system could not handle fault | P0 remediation, do not run in production |

---

## Success Criteria
- [ ] Experiment YAML passes `kubectl apply --dry-run=client`
- [ ] ChaosEngine references correct `appLabel` for target service
- [ ] At least one HTTP or Prometheus probe configured
- [ ] Experiment ran successfully in dev/staging before targeting preprod
- [ ] Resilience score ≥ 80 before considering production run
- [ ] Results documented in experiment tracker
